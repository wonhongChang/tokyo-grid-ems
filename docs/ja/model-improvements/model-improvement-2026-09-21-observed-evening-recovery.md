# 2026-09-21 実測の回復を考慮した週末夕方の残差減衰

言語: [English](../../en/model-improvements/model-improvement-2026-09-21-observed-evening-recovery.md) / [한국어](../../ko/model-improvements/model-improvement-2026-09-21-observed-evening-recovery.md)

## 問題と範囲

[9月20日の点検](../model-reviews/model-review-2026-09-20.md)では実測の回復と `non_business_evening_positive_residual_damping` の競合を確認した。9/20 17:34の実行では最新の実測傾きが+710MWだったが、過去の対象時刻の傾きが弱いため、18時の正の残差が190.1MW減衰された。元の予測自体が実測より低い状況だった。

減衰全体を無効化するのは適切ではない。9/12には過大予測を抑えた例もある。今回の変更は真の実測と対象時刻の過去パターンが共に回復を支持する場合だけ、この追加減衰を省略する。新しい需要下限や実測傾きの将来への外挿、TEPCO予測への追従は行わない。

## 適用契約

設定: `intraday_correction.non_business_evening_positive_residual_damping.observed_recovery_veto`.

| 設定 | 値 | 意味 |
|---|---:|---|
| `enabled` | `true` | 未設定/falseは既存動作を維持 |
| `max_lead_hours` | 3 | 実行時刻ではなく最後の真の実測時刻からの距離 |
| `min_latest_slope_mw` | 600 | 最新実測区間の最小上昇幅 |
| `min_mean_slope_mw` | 300 | 連続する実測二区間の最小平均上昇幅 |

既存の非営業日、対象時刻、正の基本残差、過去パターン、最小減衰量の条件を先に満たす必要がある。その上で以下をすべて要求する。

1. 連続三時間の有限な真の実測と同時刻の補正前予測が存在する。`tepco_forecast_fallback` は既存の残差入力フィルターで除外する。
2. 三時間すべての `actual - pre_calibration` が厳密に正で、二つの傾き基準を満たす。
3. 対象は最終実測から三時間以内で、有効なlag24/同営業区分の対象時刻deltaの最大値が0以上。根拠欠損または両deltaが負なら減衰を維持する。

成立時は時間減衰済みの正の残差に0.45を掛けず、そのまま維持する。前段の減衰と後段のガードは有効なままで、受け取った残差を超える復元は行わない。600/300MWは既存の夕方の負残差回復基準に合わせた値で、9/20に合わせたパラメーター探索ではない。

`residualCarryoverByHour[].nonBusinessEveningPositiveResidualObservedRecovery` に `latestSlopeMw`、`meanSlopeMw`、`minResidualMw` または `null` を記録する。理由は `non_business_evening_positive_residual_observed_recovery`。減衰省略時にも過去パターンの根拠フィールドを残す。

## Replay結果

data revision `12dc8a2952de19f572489f9b36d8880b36cfeaa9` を固定した。9/20は00~20時の実測のみ、それ以前は確定実測を使用。対象期間は8/24~9/20の28暦日。

- 28日分の補正スナップショット492件をスクリーニングした。
- 夕方の正残差減衰11実行と継続過小予測liftの29実行、重複を除く36実行を再現。保存baseline q50との差はすべて最大0.0MWだった。
- 当時のGitキャッシュ、保存された補正前曲線、当時既知の実測だけを入力した。確定した対象実測は採点専用で、外部通信は遮断した。
- 実測がある正のleadの実行/対象352組中、変化は一組だけ。同じ対象の別発表時点も含むため、独立した352時間や日次MAEの標本ではない。

残り351組は9/12の反例も含めて同一だった。後処理replayには保存q50の周囲に合成したバンドを使用し、幅の維持と境界順序を確認した。これは**再学習モデルの昇格検証でもバンドcoverage改善の証拠でもない。** 確認できた精度改善は一日の一対象であり、週末全般や季節全般の改善を示すものではない。

第二候補は正残差が三回連続で縮小するとき、継続過小予測liftの圧力を最新残差まで制限する方法だった。29実行のbaselineは再現したが不採用とした。9/6の13時は改善した一方、14時の絶対誤差が449.6→521.8MWに増加し、変化した二組のRMSEも374.71→375.72MWに悪化した。昼のliftと元の予測ロジックは変更しない。

## 検証と運用

- 外部通信を遮断したPython全体テスト717件が成功し、その後追加した実測値の回帰テスト1件も成功。欠損、fallback、非有限値、不連続時刻、0/負残差、負/欠損の支持、営業日、off、lead制限、入力不変性、バンド幅維持を検証した。個別テストは `python -m pytest tests/test_evening_positive_recovery.py -q` で実行できる。
- 学習済み `v14-r2-source-robust-day-ahead` 重み、63学習特徴量、過去予測保持、APIモデルと呼び出し予算は変更しない。
- 配信方針fingerprintは `d788cbbcd3d956a5344bf0ce2fb7d960da425390c148516acfbd40b8f9b94ee4` から `ba4d14312e56659c46a87b8e9c13750b51e93334dcb59661b8d37e6f2d0647bc` に変わる。互換のバンド補正履歴が再び蓄積されるまでは元のバンドに戻る場合がある。標本基準の緩和や非互換履歴の混在で隠さない。
- 今回の変更だけを止めるには `observed_recovery_veto.enabled: false`。旧fingerprintまで復元する場合は新ブロックを削除し、他設定も同一に保つ。
- 本番反映は通常のコード配備と予測更新後。replayで過去の公開曲線を書き換えない。平日昼の誤差、実測到着前の現在時間枠における元予測の再計算は別の未解決課題である。
