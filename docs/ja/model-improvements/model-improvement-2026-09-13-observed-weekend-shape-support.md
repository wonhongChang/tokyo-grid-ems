# 2026-09-13 週末朝のshape floorにおける観測根拠の選択

言語: [English](../../en/model-improvements/model-improvement-2026-09-13-observed-weekend-shape-support.md) / [한국어](../../ko/model-improvements/model-improvement-2026-09-13-observed-weekend-shape-support.md)

## 問題と範囲

[9月13日のレビュー](../model-reviews/model-review-2026-09-13.md)で、土曜日06〜07時の過大予測がrawモデルより`non_business_morning_shape_floor_guard`で拡大することを確認した。このguardは前日傾きと直近同営業区分の傾きの大きい方を採用するため、金曜日の通勤需要rampが土曜日の下限根拠になり得る。

9月12日05:29実行の06時rawは23,074.8MW、確定実績は22,930MWだった。前日傾き+1,550MWの採用により765.4MWを加算したが、同営業区分の傾きは+287.5MWだった。

前日傾きの一律除外は別の土曜日を悪化させたため却下した。今回の変更は**guard前の当日観測が低い予測水準を支持するときだけ**、異なる営業区分の前日傾きを除外する。学習モデル、63学習特徴量、TEPCO予測の入力方針は変更しない。

## 適用契約

設定は`adjustment.post_holiday_timeband_guard.non_business_morning_shape_floor_guard.prefer_matching_support_when_observed: true`。省略またはfalseでは今回の変更だけを無効化する。

1. 既存の非営業日条件と対象時間`[6, 7]`を維持する。
2. 既存inference contextから最初の対象時間より前の実観測のみを読む。直近二つは別々の連続時間でなければならない。対象時間内・以降の実績はこの判断に使わない。
3. 二観測のそれぞれで`actual - guard適用前の同時刻forecast <= support_slack_mw`を満たす。既存slackの250MWを使い、どちらかが高い需要水準を支持する場合は元の傾き選択を維持する。
4. `lag_24h_business_type_mismatch == 1`かつ同営業区分の傾きが有限値のときだけlag24傾きを除外する。同区分の根拠が欠ける場合は従来通りとする。
5. 残った傾きに既存floor式を適用する。根拠のない実際の予測dipは引き続き緩和する。固定需要下限やTEPCO予測追従は追加しない。

既存のshortfall 700MW、slack 250MW、shrinkage 0.75、最大lift 800MW、最小lift 100MWを維持する。p95/p99を同量移動し、guardの区間幅は変えない。feature builderは`tepco_forecast_fallback`を観測contextから除外し、当日実績contextを学習特徴量には追加しない。

観測追加で過去時間の再計算preも変わり得る。Intradayは同じ実行のpreに対して残差を再計算するため、後続のフィードバックまで一緒に検証した。既に公開した過去予測の保存方針は維持する。

## 検証と運用

- 真の早朝過小予測、観測なし・一件・非連続、欠損・非有限値、同営業区分、switch offを検証する。
- 同区分dip保護の維持、区間幅、入力不変性、後続実績の不使用、fallbackのcontext除外を検証する。
- 新設定はserving fingerprintを変更する。配備後は互換区間履歴が再度必要となり、旧policyの残差を混ぜて狭めない。最低4日・lead別24標本が揃うまでnative bandが続く可能性がある。
- switchをfalseにするか削除すれば本変更だけを取り消せる。ほかのguardと学習モデルは維持する。以前のfingerprintも復元するには新キーを削除し、ほかの設定も同一に保つ必要がある。
- 次の週末は06〜07時の過大誤差と08〜11時の残差再計算の副作用を確認する。09〜14時raw過小予測とD-1のregime偏りは別課題である。
