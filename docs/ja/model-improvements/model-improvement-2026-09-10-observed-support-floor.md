# 2026-09-10 負の残差復元に対する実測支持範囲の制限

Languages: [English](../../en/model-improvements/model-improvement-2026-09-10-observed-support-floor.md) / [한국어](../../ko/model-improvements/model-improvement-2026-09-10-observed-support-floor.md)

## 診断

9月10日19:29 JSTのPagesスナップショットには00~18時の実測があり、公開予測線のMAEは957.4MW、WAPEは3.27%、biasは+591.0MWでした。全日ではなく部分日の評価です。データrevisionは`165cc843d40f1c6f0cc02c568153d8239df284f4`です。

近距離の負の残差下限は、補正後の予測が現在の実測を既に上回っていても、過去の高需要水準に基づき最大700MWを復元していました。15:43実行の最終実測は33,400MWですが、15時対象の履歴由来下限は38,506.2MWでした。

```text
補正前35,672.1 - 残差補正1,200 + 下限復元700
  - 午後上限補正1,500 = 33,672.1 MW
```

下限復元と後段の上限制御が逆方向に作用していました。これは制御の競合であり、予測保存が元の誤差を発生させたという意味ではありません。実行ごとの再計算線と公開予測線は区別します。TEPCO予測は比較専用です。

## 変更

`IntradayResidualCorrector._negative_residual_near_term_floor_restore()`で、履歴による支持を実測水準に制限します。裏付けられた上昇時だけ限定的な余裕を設けます。

```text
observed_base = 最終実測 - 既存の下降許容幅
actual_floor = observed_base - actual_reference_slack

ramp_allowance = 初期値0
連続する2区間の実測傾きがともに正であり、
対象時間のlag24変化量と同営業タイプ変化量もともに正なら:
    ramp_allowance = min(最新実測傾き, 2区間の平均実測傾き,
                         対象lag24変化量, 対象同営業タイプ変化量) * lead

historical_floor = min(直近平均 - anchor_slack,
                       observed_base + ramp_allowance)
floor = max(actual_floor, historical_floor)
```

履歴平均が欠測でも実測由来の下限は維持します。対象変化量が欠測・非正、または先行実測が欠ける場合、上昇余裕のみを無効にします。微小な正の履歴変化量で大きな上昇を許可しません。

負の補正専用条件、最終実測から1~2時間のリード、復元上限700MW、最小復元量、下降時の減衰は維持します。復元量は元の負の補正量を超えず、このレイヤーで補正前予測より上には引き上げません。対象時間は拡張していません。復元時の余裕は`negativeResidualNearTermRampAllowanceMw`に記録し、未適用時はnullです。

## 保存証跡の検証

9月5~10日の104実行を確認しました。ローカルチェックアウトからコピーしたファイルはCRLF正規化のみを許し、固定データツリーのblob hashと照合しました。下限が適用された22行のうち4行は下限不変で、残る18行の既存復元量を再現し、14行の復元量が減りました。

変更行では後段に記録された午前・午後上限と設定済みの削減規則も再計算しました。これは**文脈を固定した下限・上限段階の再現**であり、再学習やパイプライン全体の反実仮想replayではありません。未記録の他段階の新規発動、実行間フィードバックは検証対象外です。以下は対象時間開始後の更新を除外し、同一対象は開始前の最も近い発行本を選んだ比較です。

| 日付 | 変更された事前発行対象数 | 旧MAE | 候補MAE | 改善 / 悪化 / 同一 |
|---|---:|---:|---:|---:|
| 9月5日 | 2 | 560.4MW | 332.8MW | 1 / 1 / 0 |
| 9月10日 | 5 | 881.0MW | 559.6MW | 4 / 0 / 1 |

影響を受ける一部対象の数値であり、**全日MAEの改善値ではありません**。保存された9月6~9日の実行では復元量の変更はありませんでした。

悪化例もあります。9月5日13時は実測30,130MWに対し30,121.2 → 30,035.0MWとなり、絶対誤差は8.8 → 95.0MWに増えます。最終実測だけに制限する単純案では29,613.3MWまで低下します。実測・対象変化量による余裕で副作用の大部分を抑え、特定日付の旧予測を保持する例外は加えていません。

9月10日15:43発行の16時対象は34,088.9 → 33,400MWです（実測33,250MW）。17:36発行の18時対象は33,948.5 → 33,248.5MWです（実測32,740MW）。誤差は残っており、元モデルの高需要バイアス全体を解決したとは言えません。

## テストと適用

外部ネットワークを遮断した全体テストは**628件成功**、下限・上限・区間の集中テストは126件成功しました。運用configによる後段上限の結合fixtureでは15時・16時とも33,400MWとなり、旧出力から単純に700MWを引いた結果ではありません。

回帰テストでは低需要の横ばい、実測上昇、弱い・欠測・不一致の支持、観測欠落、下降許容幅、復元上限、入力・観測済み区間の不変性、p95/p99移動の整合性を確認します。政策fingerprintのテストは旧来の無制限な履歴下限を識別します。テストプロセスの外部ネットワークを遮断し、有料API呼び出し、ETL再実行、学習は不要です。

学習済み`v14-r2-source-robust-day-ahead`のartifactと重みは不変です。q50後処理が変わるため`servingSemanticsVersion`を**2**に上げます。旧政策スナップショットを新しい区間補正履歴に混ぜません。互換証跡が十分になるまでnative区間の正規化・上限制御を維持し、区間縮小や実測包含率95%は保証しません。

配備後は通常のIntraday実行が未観測対象に新規則を使います。改善を示すために既公開の観測済み区間や過去のスコアを書き換えません。新fingerprintで復元量・上昇余裕、区間の順序、事前発行誤差を確認します。

## 残る課題

- 設計確定後、22:29 JSTにPagesを別途確認すると19~20時の実測31,570 / 29,990MWが追加されていました。保存した19:29再計算に最終候補を適用しても700MW復元は維持され、32,145.6 / 31,156.3MW、誤差+575.6 / +1,166.3MWのままです。19時は対象区間開始後の更新、20時は事前予測です。補正入力が既に実測支持下限より低く、過大な履歴水準の制限だけでは予想される夕方下降まで解決できない証拠です。上表の改善対象には含めていません。
- 午後上限には対象時間、リード、最終観測時間の別々の境界があります。17:36実行では`lastObservedHour=16`が設定上限15を超え、横ばいの実測傾きは夕方下降条件にも該当しませんでした。下方制御が追加解除された理由です。時間・リード延長は境界を移すだけで安全な引継ぎを証明しないため、今回は含めません。
- 午前の元モデルの天候・lag感度と日付境界の初期補正は別の除去実験対象です。本日の誤差全体をこの下限に帰属しません。
- 次の検証は発行時点の入力で、支持された再上昇、一時的な昼休みdip、涼しい平日、週末を含めます。対象時間の診断と全日・長期の回帰検証を併用します。
