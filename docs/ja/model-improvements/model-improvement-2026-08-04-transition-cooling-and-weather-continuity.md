# 営業日遷移の冷房減衰と気象連続性

## 運用事象

2026-08-03の営業日予測は、確定した24時間すべてで過大予測でした。配信MAEは1,668.7 MW、平均biasは+1,668.7 MWで、24時間中21時間はTEPCO予測の絶対誤差が小さい結果でした。誤差は00時から存在し、午前後半から夜にかけて再び拡大しました。2026-08-04も確定済みの最初の16時間では正のbiasが残り、特に06時と07時の誤差が大きくなりました。

TEPCO予測は外部benchmarkとしてのみ使用しました。モデル入力、target、anchor、補正値には使用していません。

## 原因の分離

独立した二つの問題を確認しました。

1. 営業日のq50は、絶対需要q50と`lag_24h + 残差q50`を固定50:50で合成していました。日曜から月曜へ移る8月3日は`cooling_delta_24h`が約-8~-10度でしたが、残差推定が絶対需要q50に最大約3.7 GWを追加しました。Intraday補正は-1,200 MWのcapまで作動しましたが、raw誤差の方が大きく回復できませんでした。
2. 旧weather bias補正より先に、過去予報行がAMeDAS実績で置き換えられていました。その後の比較では実績同士を比較してbiasが0になる場合が多くありました。8月3日朝は07時AMeDASの22.9度から08時JMA予報の26.1度へ不連続に接続し、気象感応featureと週次Challengerのprediction driftを拡大しました。

Published forecast freezeは主原因ではありません。公開済みの過去点は保持されましたが、未来点にはintraday下方補正が実際に適用されていました。支配的な問題はraw q50の水準でした。

## 変更内容

### 1. 遷移日の残差weight減衰

v13 Challengerは通常の営業日では既存の残差合成を維持します。前日と営業タイプが異なる営業日にのみ、時間別weightを計算します。

```text
effective_weight = configured_weight * clip((cooling_delta_24h - (-4)) / (0 - (-4)), 0, 1)
```

- `cooling_delta_24h >= 0度`: 設定値0.5を維持します。
- `cooling_delta_24h <= -4度`: 残差合成を止め、絶対需要q50を使用します。
- -4度から0度: 連続的に減衰します。

この規則はv13モデル契約です。現行v11 Championには強制適用せず、昇格gate通過後にのみ配信します。

### 2. AMeDAS-JMA気温連続性補正

直近AMeDAS実績の後に続く最初の当日JMA予報を次の手順で処理します。

- 連続した直近の時間変化を最大3件使い、観測気温slopeを推定します。
- 観測slopeを1時間あたり+/-1.0度に制限します。
- 最終観測から投影した次時刻の気温と最初のJMA予報を比較します。
- 差が1.5度以上の場合のみ作動します。
- 差を+/-2.5度に制限し、70%だけ反映して次の3時間へ0.6ずつ減衰します。

補正対象はメモリ上のモデル入力だけです。AMeDAS実績、永続化するsource気温、dashboard表示気温は上書きしません。

84日gateは通過しました。一方、直近28日MAEは絶対上限1,000 MWを36.6 MW上回りました。そのためChallengerは引き続き拒否され、v11がChampionとして維持されます。この変更を通すためにthresholdを緩和していません。

同じ検証モデルの2026-08-03 MAEは、固定残差合成で2,865.3 MW、減衰適用で1,973.8 MWでした。主要な増幅要因は抑えましたが、絶対需要q50にも誤差が残るため、この変更だけですべて解決したとは判断しません。

### 気象snapshot replay

利用可能なlive ETLの予報・実績比較18件で、近距離気温MAEは1.926度から1.302度へ、最大誤差は4.00度から2.95度へ低下しました。選択したthreshold、cap、shrinkage、decayでは18件すべて改善し、悪化は0件でした。

## 不採用とした案

- すべての営業タイプ遷移で残差モデルを無効化すると、気温が下がらない遷移日が悪化しました。
- 営業日復帰専用q50モデルは全体replayと8月3日の両方を悪化させました。
- 湿度・不快指数featureを全体から外すと長期replayが悪化しました。
- 学習履歴を直近180日、365日、730日に制限した実験は全履歴より悪化しました。
- 遷移interaction feature追加とLightGBM leaf複雑度変更は絶対品質gateを通過しませんでした。
- 昇格MAE基準とprediction drift上限は緩和していません。

## 運用状態

- 気象連続性補正はdeploy後、ETLとintradayのモデル入力へ即時適用されます。
- q50変更は、週次昇格処理で時系列・segment・絶対品質・prediction drift gateをすべて通過するまでChallengerのままです。
- 急に涼しくなった営業日復帰と通常営業日を分けて継続監視します。
