## 原因分解

### 8月14日: 夕方の予報気象境界

- 17時と18時の誤差は約+1.65GW、+2.22GWだった。
- 配信時raw q50は将来JMA気温入力により高い水準を維持した。日終了後にAMeDAS観測気象で再計算したraw q50は同時間の実績に近づいた。
- `negative_residual_near_term_floor`が約700MWを復元して過大誤差を広げた区間はあるが、主因は残差controllerではなく配信時気象入力だった。

### 8月15日: 14〜16時のV字shape

- 14時と16時の誤差は約+2.84GW、+2.89GWだった。
- 13:30と15:30 snapshotのraw q50に大きなV字反発がすでに存在した。最終観測気象で再計算したraw q50は14〜16時の実績に近かった。
- この事例は単一のLightGBM需要mappingより、AMeDAS-JMA境界後の将来気象revisionの影響が大きい。

### 8月16日: 非営業日の原型regime誤差

- 00時は約+2.48GW、18時は約-2.31GWで方向が逆だった。
- 最終観測気象で再計算したraw q50にも夜間過大と夕方過小が残った。
- 気象境界だけでは説明できない非営業日のlevelおよびshape問題であり、一つの週末guardで両方向を同時補正するのは危険である。

### 8月17日: 営業復帰rampの過小予測

- 09時誤差は-2.41GW、朝biasは-1.13GWだった。
- 直近同一営業種別の朝rampは`lag_24h` rampより強かった。現在の`business_return_anchor_shortfall`は先に6,000MWのlevel gapをgateとするため、08時は+1,000MW補正されたが09時はgateを通過しなかった。
- 他の営業種別遷移日の朝biasは8月10日+806MW、12日+1,336MW、17日-1,135MWで方向が一定しない。17日だけを根拠にlevel gateを緩和すると10日と12日を悪化させる可能性がある。

### 8月18日: 朝guardと残差の符号反転

- 08時は-1.81GW、09時は-0.71GWの過小となり、10時と11時は+0.66GW、+0.73GWの過大へ反転した。
- 09時の`LocalizedShapeSpikeGuard`は約814MW下げたが、直近の当日実績が1時間で+5.81GW上昇している事実をveto条件に持たず、過小予測を悪化させた。
- 11時のraw q50は実績との差が約44MWでほぼ正確だったが、warm-day/post-holiday補正と正の残差carryoverにより最終誤差は約+730MWになった。
- 安全な候補は09時専用の例外ではなく、強い直近実績rampとshape guardの方向が衝突した場合の一般的なvetoである。残差が収束して符号反転する場合のrecency dampingもshadow replayで評価する。

### 昼休みshape

8月17日の実際の11→12時変化は-350MWだったが、モデルは-1,970MWを予測した。現在のMidday Guardは不足したdipを追加する一方向guardであり、すでに深いraw dipを持ち上げない。営業復帰日1件だけでは対称liftを追加しない。

## FreezeとIntradayの判断

Published Forecast Freezeは維持する。8月14、16、17日は多くの時間で実配信線が日終了後の再計算raw線より正確だった。特に8月17日はIntraday補正が昼間の大きなraw過小予測を相当緩和した。

現在のstage replayは日付ごとの最終snapshotのみを使用し、28日のうちstage snapshotがあるのは13日である。最終snapshotは最終観測気象に近いため、配信時気象誤差とFreeze効果を完全には再現できない。stage集計だけを根拠にFreezeやguardを削除しない。

## Challenger昇格判断

2026-08-17の週次候補における直近28日検証結果は次の通り。

| 指標 | 候補 | 絶対基準 | 結果 |

| 全体MAE | 1,262.2MW | 1,000MW以下 | 失敗 |
| 全体WAPE | 3.590% | 3.0%以下 | 失敗 |
| 昼間MAE | 1,669.6MW | 1,500MW以下 | 失敗 |
| Shape delta MAE | 604.7MW | 750MW以下 | 合格 |
| 最大誤差 | 5,121.5MW | 6,500MW以下 | 合格 |

予測driftは有効だったが、絶対品質gateを3件失敗した。fail-closed昇格方針が正しくChampionを維持した。

同一offline期間で配信v11を再現するとMAEは約1,500MW、v13は約1,276MWだった。source境界に敏感な気象delta 4個を除外し、営業/非営業q50のblendとresidual weightを探索した最良の単純候補でも、MAE 1,245MW、WAPE 3.56%、昼間MAE 1,576MWだった。v11より改善したが絶対gateは未通過である。v11を健全な長期モデルと見なすべきではない一方、gateを下げてv13を即時昇格するのも安全ではない。

最終の同一cutoff契約replayでは、v13対v11は28日で1,275.8対1,351.7MW（5.62%改善）、56日で983.8対1,016.0MW（3.17%）、84日で891.6対916.8MW（2.75%）だった。全期間で方向は良いが、性能低下Championの復旧基準10%には届かない。したがって判断は**昇格なし**である。v11を暫定維持しつつ、v13を運用品質と再定義せず、証拠を保存して新Challengerを開発する。

過去の同一実行vintage初期復元は14日、paired row 911件だった。lead bucket別TEPCO比MAEは1.84〜2.20だが、28/84日coverage、risk比率、paired信頼区間が完成するまでは正式状態を`collecting`とする。

## 予測Band

直近28日のp95 coverageは94.9%で、目標95%に近い。非営業日は92.1%、朝は90.7%、夕方前半は89.3%と不足し、夜は100.0%で広い。

## 後続課題

配信動作を変更する前に、次の候補を直ちに実装またはshadow replayする。

1. 運用snapshotにAMeDAS-JMA境界の`raw_gap`、`continuity_bias`、補正後`remaining_gap`、気象sourceを保存する。
2. `LocalizedShapeSpikeGuard`に直近の当日実績rampとの方向衝突vetoを追加し、28日serving replayで回帰を確認する。
3. 最近の残差が急速に収束または符号反転する場合のresidual carryover減衰をshadow評価する。
4. artifact metadataに学習cutoffと現config fingerprint互換性を必須化し、昇格reportにChampion比のChallenger性能を明示する。
5. 単純な営業日専用q50 blendはgateを通過しなかったため、時間shapeを直接扱う候補と非営業日の夜間level・夕方shapeを分離した候補を比較する。

これらの項目は今回のレビューでserving configに適用していない。
