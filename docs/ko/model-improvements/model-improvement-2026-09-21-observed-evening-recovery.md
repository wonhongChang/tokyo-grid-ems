# 2026-09-21 실측 회복을 고려한 주말 저녁 잔차 감쇠

언어: [English](../../en/model-improvements/model-improvement-2026-09-21-observed-evening-recovery.md) / [日本語](../../ja/model-improvements/model-improvement-2026-09-21-observed-evening-recovery.md)

## 문제와 범위

[9월 20일 점검](../model-reviews/model-review-2026-09-20.md)에서 실측 회복과 `non_business_evening_positive_residual_damping`의 충돌을 확인했다. 9/20 17:34 실행의 최신 실측 기울기는 +710MW였지만, 과거 패턴의 타깃 시간 기울기가 약하다는 이유로 18시 양수 잔차가 190.1MW 줄었다. 원형 예측부터 실측보다 낮은 상황이었다.

감쇠 전체를 끄는 것은 적절하지 않다. 9/12에는 과대예측을 제한하는 데 도움이 된 사례가 있다. 이번 변경은 진짜 실측과 타깃 시간의 과거 패턴이 함께 회복을 지지할 때만 이 추가 감쇠를 생략한다. 새 수요 하한선을 만들거나, 실측 기울기를 미래 수요로 외삽하거나, TEPCO 예측을 따라가지 않는다.

## 적용 계약

설정: `intraday_correction.non_business_evening_positive_residual_damping.observed_recovery_veto`.

| 설정 | 값 | 의미 |
|---|---:|---|
| `enabled` | `true` | 미설정/false이면 기존 동작 유지 |
| `max_lead_hours` | 3 | 실행 시각이 아닌 마지막 진짜 실측 시간에서의 거리 |
| `min_latest_slope_mw` | 600 | 마지막 실측 구간의 최소 상승폭 |
| `min_mean_slope_mw` | 300 | 연속 두 실측 구간의 최소 평균 상승폭 |

기존 비영업일·타깃 시간·양수 기본 잔차·과거 패턴·최소 감쇠량 조건을 먼저 만족해야 한다. 그 뒤 다음 조건이 모두 필요하다.

1. 연속 세 시간의 유효한 진짜 실측과 동시간대 보정 전 예측이 존재한다. `tepco_forecast_fallback`은 기존 잔차 입력 필터에서 제외한다.
2. 세 시간 모두 `actual - pre_calibration`이 엄격히 양수이며, 두 기울기 기준을 만족한다.
3. 타깃은 마지막 실측에서 3시간 이내이고, 유효 lag24/동영업유형 타깃 기울기 중 최댓값이 0 이상이다. 근거가 없거나 두 기울기가 모두 음수이면 감쇠를 유지한다.

통과하면 이미 시간 감쇠가 적용된 양수 잔차에 0.45를 곱하지 않고 그대로 유지한다. 앞선 감쇠와 뒤의 가드는 계속 적용하며, 입력으로 받은 잔차보다 더 복원하지 않는다. 600/300MW 기준은 기존 저녁 음수 잔차 회복 기준과 맞췄으며, 9/20에 맞춘 파라미터 탐색으로 선정하지 않았다.

`residualCarryoverByHour[].nonBusinessEveningPositiveResidualObservedRecovery`에 `latestSlopeMw`, `meanSlopeMw`, `minResidualMw` 또는 `null`을 남긴다. 사유는 `non_business_evening_positive_residual_observed_recovery`이며, 감쇠 생략 시에도 과거 패턴 근거 필드를 보존한다.

## Replay 결과

data revision `12dc8a2952de19f572489f9b36d8880b36cfeaa9`를 고정했다. 9/20은 00~20시 실측까지만 사용하고 이전 날짜는 확정 실측으로 평가했다. 범위는 8/24~9/20의 28개 날짜다.

- 28일에 걸친 보정 스냅샷 492개를 선별 검사했다.
- 저녁 양수 잔차 감쇠가 있었던 11개 실행과 지속 과소예측 lift가 있었던 29개 실행, 중복 제외 36개 실행을 재현했다. 기록된 baseline q50과의 최대 차이는 모두 0.0MW였다.
- 당시 Git 캐시, 저장된 보정 전 곡선, 그때 알려진 실측만 입력했다. 확정 타깃 실측은 채점에만 사용했고 외부 네트워크는 차단했다.
- 실측이 있는 양수 lead의 실행/타깃 352쌍 중 한 쌍만 변경됐다. 서로 다른 실행의 같은 타깃이 포함되므로 독립된 352시간이나 일간 MAE 표본이 아니다.

| 타깃 / 실행 | 실측 MW | 기존 MW | 수정 MW | 절대오차 전 / 후 MW |
|---|---:|---:|---:|---:|
| 9/20 18시 / 17:34 | 29,240.0 | 28,548.7 | 28,738.8 | 691.3 / 501.2 |

나머지 351쌍은 9/12 반례를 포함해 동일했다. 후처리 replay에서는 저장된 q50 주변에 합성 밴드를 사용했다. 폭 보존과 경계 순서는 검사했지만 **재학습 모델 승격 검증이나 밴드 커버리지 개선의 근거는 아니다.** 확인된 정확도 개선은 한 날짜의 한 타깃이며, 일반적인 주말·계절 성능 개선을 입증한 것은 아니다.

두 번째 후보는 양수 잔차가 세 번 연속 감소하면 지속 과소예측 lift의 압력을 최신 잔차로 제한하는 방식이었다. 29개 baseline은 모두 재현했지만 기각했다. 9/6 13시는 개선됐으나 14시 절대오차가 449.6→521.8MW로 커졌고, 변경된 두 쌍의 RMSE도 374.71→375.72MW로 악화됐다. 낮 lift와 원형 예측 로직은 변경하지 않았다.

## 검증과 운영

- 외부 네트워크를 차단한 Python 전체 테스트 717개가 통과했고, 이후 추가한 실측 수치 회귀 테스트 1개도 통과했다. 개별 테스트는 결측·fallback·비유한 값·불연속 시간·0/음수 잔차·음수/결측 근거·영업일·스위치 off·lead 제한·입력 불변성·밴드 폭 보존을 다룬다. 실행 명령은 `python -m pytest tests/test_evening_positive_recovery.py -q`다.
- 학습된 `v14-r2-source-robust-day-ahead` 가중치, 학습 피처 63개, 과거 예측 보존, API 모델 및 호출 예산은 그대로다.
- 서빙 fingerprint는 `d788cbbcd3d956a5344bf0ce2fb7d960da425390c148516acfbd40b8f9b94ee4`에서 `ba4d14312e56659c46a87b8e9c13750b51e93334dcb59661b8d37e6f2d0647bc`로 바뀐다. 호환되는 밴드 보정 이력이 다시 쌓여야 하므로 일시적으로 기본 밴드가 표시될 수 있다. 이를 숨기려고 표본 기준을 낮추거나 다른 정책의 이력을 섞지 않는다.
- 이 변경만 끄려면 `observed_recovery_veto.enabled: false`로 둔다. 이전 fingerprint까지 복원하려면 새 블록을 제거하고 나머지 설정도 동일하게 유지한다.
- 실제 적용은 정상적인 코드 배포와 예측 갱신 이후다. replay로 과거 게시선을 다시 쓰지 않는다. 평일 낮 오차와 실측 입고 전 현재 시간 버킷의 원형 재계산 문제는 별도 미해결 과제다.
