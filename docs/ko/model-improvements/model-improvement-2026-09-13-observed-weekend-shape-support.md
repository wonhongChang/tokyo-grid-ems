# 2026-09-13 주말 아침 shape floor의 관측 근거 선택

언어: [English](../../en/model-improvements/model-improvement-2026-09-13-observed-weekend-shape-support.md) / [日本語](../../ja/model-improvements/model-improvement-2026-09-13-observed-weekend-shape-support.md)

## 문제와 범위

[9월 13일 점검](../model-reviews/model-review-2026-09-13.md)에서 토요일 06~07시의 과대예측이 원형 모델보다 `non_business_morning_shape_floor_guard`에서 커지는 것을 확인했다. 이 가드는 전날 기울기와 최근 같은 영업유형의 기울기 중 큰 값을 사용한다. 금요일의 출근 수요 증가폭이 토요일의 하한선 근거가 될 수 있었다.

9월 12일 05:29 실행에서 06시 raw는 23,074.8MW, 확정 실측은 22,930MW였다. 전날 기울기 +1,550MW를 선택하면서 가드가 765.4MW를 추가했다. 최근 같은 영업유형의 기울기는 +287.5MW였다.

전날 기울기의 일괄 제외는 다른 토요일을 악화시켜 기각했다. 이번 수정은 **당일의 가드 이전 관측이 낮은 예측 수준을 뒷받침할 때만** 영업유형이 다른 전날의 기울기를 제외한다. 학습 모델, 63개 학습 피처, TEPCO 예측 입력 정책은 바꾸지 않는다.

## 적용 계약

설정은 `adjustment.post_holiday_timeband_guard.non_business_morning_shape_floor_guard.prefer_matching_support_when_observed: true`다. 빠져 있거나 false이면 이 변경만 비활성화된다.

1. 기존 비영업일 가드의 대상 시간 `[6, 7]`과 활성화 조건을 유지한다.
2. 기존 inference context에서 첫 대상 시간 이전의 실제 관측만 읽는다. 최근 두 관측은 서로 다른 연속 시간이어야 한다. 가드 대상 및 이후 시간의 실측은 이 판단에 쓰지 않는다.
3. 두 관측 각각에서 `actual - 가드 적용 전 동일 시간 forecast <= support_slack_mw`여야 한다. 기존 slack 250MW를 사용한다. 하나라도 실제 수요가 더 높은 수준을 지지하면 기존 기울기 선택을 유지한다.
4. `lag_24h_business_type_mismatch == 1`이고 최근 같은 영업유형 기울기가 유효할 때만 lag24 기울기를 후보에서 제외한다. 최근 동유형 근거가 없으면 기존 동작을 보존한다.
5. 남은 동유형 기울기로 기존 floor 공식을 적용한다. 실제로 근거 없는 하락은 여전히 완충한다. 새 고정 수요 하한선이나 TEPCO 예측 추종은 없다.

기존 700MW shortfall, 250MW slack, 0.75 shrinkage, 800MW 최대 lift, 100MW 최소 lift를 유지한다. 가드가 이동시키는 p95/p99 폭은 바꾸지 않는다. source가 `tepco_forecast_fallback`인 값은 feature builder가 관측 context에서 제외하며, 학습 피처에는 당일 실측 context를 추가하지 않는다.

관측이 추가되면 가드 이전 시간의 재계산 예측도 달라질 수 있다. Intraday는 이 실행의 pre-calibration과 실측으로 잔차를 다시 계산하므로, 이후 보정까지 함께 검증했다. 이미 게시된 과거 예측선 보존 정책은 변경하지 않는다.

## 재생 결과

과거 Git cache, 당시 알려진 관측, 저장된 raw/상위 level/analog 출력을 사용했다. timeband부터 Intraday까지 재계산한 51개 실행 중 기준 pre/post가 재현된 48개만 평가했다. 정책 차이로 불일치한 3개는 제외했다. 각 타깃의 시작 전 0~2시간 중 가장 가까운 발행본 하나를 선택했다.

9월 12일의 같은 12개 타깃 WAPE는 2.06%→1.53%, 최대 절대오차는 1,066.0→829.1MW다. 06시 23,843.0→23,077.6MW, 07시 24,963.0→24,483.6MW로 바뀐다. 앞선 과대 floor가 잔차를 더 음수로 만드는 효과도 줄어 09~11시 일부 과소예측이 완화됐다. 반면 08시는 26,021.2→26,154.1MW로 올라 실측 25,710MW에서 더 멀어졌다. 모든 시간이 개선된 것은 아니다.

같은 9월 12일 2~4시간 lead MAE는 671.3→519.8MW, 4~8시간은 685.8→649.4MW였다. 나머지 비교일의 해당 lead 결과는 불변이었다. 저장된 8월 14일~9월 10일 D0/D-1 각 672개 origin 예측도 전부 불변이었다.

이것은 **고정 raw 기반 q50 후처리 재생**이며 새 학습 artifact의 28일 승격 검증이 아니다. 합성 band 경계로 잔차 피드백을 재생했으므로 전체 구간 보정 성능까지 증명하지 않는다. 특히 조건부 안의 활성화 이득은 한 토요일에 관측된 결과이며 계절 전반의 개선을 보장하지 않는다.

## 검증과 운영

- 원형 모델이 실제 수준보다 낮은 반례, 근거 없음/한 관측/비연속 관측, 결측·비유한값, 동일 영업유형, switch off를 검증한다.
- 실제 동유형 하락 지지, band 폭 유지, 입력 불변성, 이후 실측 비사용, fallback의 관측 context 제외를 검증한다.
- 변경 설정은 serving fingerprint에 포함된다. 배포 후 새 정책의 interval 이력이 다시 필요하며, 이전 정책의 잔차를 섞어 폭을 억지로 줄이지 않는다. 최소 4일·lead별 24표본 충족 전에는 native band가 유지될 수 있다.
- 롤백은 위 switch를 false로 되돌리거나 제거한다. 다른 가드와 원형 모델은 그대로 둔다. 이전 fingerprint까지 되돌리려면 새 키를 제거해야 하며 다른 설정도 동일해야 한다.
- 다음 주말에는 06~07시 과대오차뿐 아니라 08~11시 잔차 재계산 부작용도 점검한다. 09~14시 raw 과소예측과 D-1 레짐 편향은 별도 과제다.

## AI 리포트 근거 수정

전체 Python 테스트는 외부 네트워크 차단 상태에서 678개가 통과했다. 정책 fingerprint는 `853044a84f4e160432f5784503df71de0621978c4ecac19183f169be052fc28b`에서 `d788cbbcd3d956a5344bf0ce2fb7d960da425390c148516acfbd40b8f9b94ee4`로 바뀐다. 학습 artifact hash는 바꾸지 않는다.

공개선과 사후 재계산선의 차이만 있는 `published_recalculated_gap` 이벤트는 모델 튜닝 ticket을 만들지 않도록 했다. 실제 수요 오차가 거의 없는 17시를 저녁 가드 결함으로 추천하던 오류를 막는다. 실제 오차 이벤트는 유지하고, ticket은 최종 보고서에 남은 가설 ID에 연결한다. 이 변경은 en/ko/ja 공통 경로에 적용된다. OpenAI 모델·호출 횟수·비용 설정은 변경하지 않았다.
