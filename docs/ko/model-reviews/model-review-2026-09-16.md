## 4. 후보 검증과 기각 이유

### A. 기상 입력 민감도 평균화

미래 예보 기온만 ±0.5°C 또는 ±1.0°C로 바꿔 파생 피처를 다시 만들고 원래 raw와 평균냈습니다. 실측 기온은 유지했으며, 이는 검증된 기상 오차 분포가 아닌 제한된 민감도 실험입니다.

- 8/14~9/10 D0 origin 28개와 9/14~16 실행 26개를 복원했습니다. 54/54 baseline 재현 검사를 통과했습니다.
- 28일 양의 lead 639행 raw MAE: 원본 **1385.9** → ±0.5°C **1392.2**, ±1.0°C **1391.6**. 평일·비영업일 모두 악화했습니다.
- 최근 실행 297개 미래 행은 1118.6 → 1109.6 / 1117.4였으나, 과거 구간 개선으로 이어지지 않았습니다. 여러 발표 시점의 행을 포함하므로 일별 게시선 MAE가 아닙니다.
- **기각:** raw 단계에서 악화하여 전체 후처리 replay나 운영 반영으로 진행하지 않았습니다.

### B. 이미 낮은 예측에 대한 cooler-day prior 제한

기존 lag 과열 기반 음수 보정량을 현재 예측과 동유형 anchor의 양수 차이 이내로 제한하는 후보를 검증했습니다. 중복 하방 보정을 줄이는 목적이었습니다.

- 8/19~9/16 보관 기록에서 해당 보정이 활성화된 실행 10개를 찾아 10/10 baseline을 정확히 재현했습니다.
- 0~2시간의 날짜·시간별 15개 대상 중 9/16 MAE는 550.7 → 494.6MW, 9/10은 705.6 → 461.5MW로 개선됐습니다.
- 그러나 실측이 있는 양의 lead 215행 전체는 **1002.9 → 1032.6MW**로 악화했습니다. 9/10은 1315.6 → 1483.1MW, 일부 낮 시간에는 유효한 하방 보정이 사라져 약 700MW 더 나빠졌습니다.
- **기각:** 근거리 개선만 보고 하루 전체에 적용하지 않았습니다. 이 후보는 기존 모델·prior를 폐기해도 된다는 근거가 아닙니다.

## 5. 채택한 리포트 수정

9/15 입력에서 화요일 08시 오차를 시간대만 보고 영업일 전환 가드에 연결하고, 16~17시에는 명확한 실측 하락·예측 반등 없이 저녁 cap을 추천하던 규칙을 확인했습니다.

1. 오전은 lag·동유형·기상·보정 단계를 비교하는 조사 후보로 생성합니다. 영업일 전환 설명은 명시적 mismatch 근거가 있을 때만 허용하고, 그 사실만으로 원인을 확정하지 않습니다.
2. 저녁 하락 cap의 자동 후보에는 양수 오차, 실측 하락, 예측 상승의 수치 근거를 함께 요구합니다.
3. 한국어·일본어 리포트의 생성형 보완 문구에 영어가 섞이던 경로를 수정했습니다.
4. 리포트 재생성 명령을 모델 replay 명령처럼 제시하던 항목을 제거했습니다.

네트워크를 차단한 관련 테스트 **74개 통과**. 실제 9/15 입력의 세 언어 문맥을 오프라인 재구성해 잘못된 추천 제거도 확인했습니다. 이것은 유료 AI 재생성이나 전체 리포트 품질 점수의 보증이 아닙니다. 기존 공개 리포트 JSON은 덮어쓰지 않았습니다. 규칙은 [AI 리포트 가드레일](../ai-report-guardrails.md)에 반영했습니다.
